Programs preserve authored targets and instructions. Weight entry remains manual; instructions never execute code or predict a load.

A routine exercise may carry `target: {rir?, rpe?, pct?}` as its default, and `setTargets` as an ordered array of overrides for working sets. Each target value is a finite number (RPE/RIR 0–10, percentage greater than zero). The importer preserves RPE as RPE and RIR as RIR; an explicitly authored effort replaces a default effort in either scale. At session creation these targets are frozen onto each working row's `target`, separate from the row's logged `rir`/`rpe`. Warmups have no authored work target. Workout rows, Focus view, session previews, week badges and generated queue labels display effort in the profile’s selected RIR/RPE scale (RPE = 10 − RIR), including half-points and ranges. Percent-of-TM targets are unchanged. With effort tracking off, targets keep their authored scale (`@8`, `2 RIR`, or `75%`). Settings → Workout and the in-workout settings sheet provide an Effort scale selector and a separate “Don’t track effort” switch; selecting a scale updates the current workout immediately. Already-logged effort fields retain their own scale.

`instructions` is an optional plain string on an exercise or definition. Exercise cards and previews show it, including conditional drop, repeat-until and total-rep rules. Importers convert supported progression scripts into instructions without executing them. Rep ranges use the existing `repsMin`/`reps` pair when uniform, or `setRepsMin` alongside the pyramid when targets differ by set; the started rows freeze their range as `repTarget: {min,max}`.

Legacy `tm: {key, percentages}` prescriptions keep their percentages. A cycle's matching `tm[key]` is optional; if positive, its derived weights use the existing unit and plate rounding. Missing training maxes never prevent Start.

Exercise Settings preserve authored targets and instructions in both routines and workouts. Removing sets trims their targets; adding sets repeats the final set's prescription. Turning off a pyramid retains displayed percentages in `setTargets`. The API also preserves these fields when an older stamped bundle saves a whitelist of exercise settings.

Live starts respect the program's chosen start date and shift bound. Ending or switching releases scheduling ownership while retaining `programmeHistory: {cycleId, series}` on routines for legacy history lookup. Late offline finishes keep their logs without restoring a terminal cycle's queue; a running successor retains its queue. Inserted deloads replace copied effort targets with the deload's RIR while keeping percentages.

An exercise slot can be `{open: true, label: 'Accessory, your pick', slotId: 'accessory', sets: 3, repsMin: 10, reps: 15, target: {rir: 2}}` without an exercise ID. It starts as a picker card. Choosing an existing or custom exercise retains the slot's prescription and freezes an ordinary exercise entry for normal logging. The choice becomes the default in the current and later pending occurrences of the same slot/session; completed logs and unrelated slots stay intact. A chosen slot can be changed before any of its sets is completed. Unchosen slots cannot produce exercise logs.

The pure `packages/core/src/programme-refresh.ts` helper prepares refreshed definitions; a private runtime library is not an input to this source distribution. No private program content is bundled with the app or stored in this repository.


Conversion creates display copies only; authored targets and logged effort never change. `lastEffortScale` remembers the profile's most recent RIR/RPE choice while tracking is off, and the segmented selector has no highlight in that state. Older clients preserve this optional setting through the existing unknown-field compatibility path.

Planner-generated notes carry `noteKind: 'planner'`. Unmarked notes are opaque, regardless of their text or program IDs. Generated queue labels use their cycle reference or `labelKind: 'planner'` to convert only the final effort suffix. Existing notes require an explicit offline migration with known provenance; the app never guesses from personal IDs.

Each imported exercise config, including split configs and private imports, stores `generatedRules` containing only numeric rule values and finite structural tags, plus separate `authoredInstructions`. `instructions` retains the authored-scale combined fallback for old clients. Display conversion reconstructs generated text from the structured rules and appends authored text verbatim, even when the two strings are identical. Older imports without that structural provenance retain their original prose until refreshed from their source file. Exercise Settings and API compatibility saves retain the new provenance fields.

MCP `get_routine` and `preview_session` return profile-scale targets plus `authored_target` and `target_label`, preserving percentages. `get_workout` adds `display_target` and per-set targets while historical set labels retain their logged scale. `get_programme` retains `definition`/`cycle` as authored and adds `effortScale` and `displayDefinition`. These are read-only projections.
